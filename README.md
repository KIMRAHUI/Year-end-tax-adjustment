
# 연말정산 도우미 — RAG 에이전트 챗봇

국세청 「2024년 연말정산 신고안내」(PDF 426쪽)를 근거로 답하는 에이전트형 RAG 챗봇입니다. 미션 14(RAG → 에이전트 확장)의 결과물로, 노트북에서 실험한 구조를 Streamlit 웹 앱으로 배포했습니다.

| 제출물 | `14_2팀_김라희.ipynb` (실험·평가), 이 저장소 (배포용 앱) |

## 한눈에 보기

| 지표 | 값 |
|---|---|
| 근거 문서 | 국세청 2024 연말정산 신고안내, 426쪽 |
| 평가 세트 | 도메인 질문 28개 + 황금 답변 (노트북) |
| 비교 조건 | 12가지 구성 × 28문항, 문서 없이 답하는 기준선(E0) 포함 |
| 채점 | 규칙 점수 + LLM 판정(gpt-oss-120b) |
| 배포 모델 | Groq `gpt-oss-120b` (기본), `gpt-oss-20b` 선택 가능 |
| 검색 | BM25(글자 2-gram) + bge-m3 dense → RRF |
| 도구 | 문서 검색 1개 + 계산 4개 |
| 실행 위치 | Streamlit Community Cloud (CPU 전용, 약 2.7GB 메모리) |

세부 점수와 표는 노트북에 있으니 이 문서에는 숫자를 다시 옮기지 않았습니다.

## 핵심 설계 결정과 근거

### 검색 · 에이전트

| 질문 | 결정 | 근거 |
|---|---|---|
| 왜 에이전트인가? | LLM이 `search_tax_docs`를 필요할 때만 부르는 도구 호출 구조 | 항상 검색하는 고정 파이프라인보다 "계산만 필요한 질문"에서 불필요한 검색이 줄어듭니다 |
| 왜 하이브리드 검색인가? | BM25(글자 2-gram)와 bge-m3 dense를 RRF로 합침 | 세액공제 이름·금액 같은 정확한 단어(BM25)와 의미가 같은 다른 표현(dense)을 둘 다 잡기 위해서입니다 |
| 왜 글자 2-gram인가? | 한국어 형태소 분석기 없이 BM25 토큰화 | 조사가 붙은 말("월세를", "월세의")이 서로 맞게 하려는 가벼운 방법입니다 |
| 노트북의 심화 기법은? | reranker, CRAG, multi-query, contextual compression 등을 구성별로 비교 | 구성마다 채점해 어느 기법이 도움이 됐는지 노트북에서 확인했습니다 |
| 계산은 어떻게 하나? | 근로소득공제, 월세·연금계좌·자녀 세액공제를 코드 도구로 분리 | LLM이 직접 계산하면 틀립니다. 계산은 코드가, 규정 찾기는 문서가 맡게 했습니다 |
| 대화 맥락은? | `InMemorySaver`에 thread_id를 두고 세션마다 기억 | 같은 세션에서 "그럼 자녀가 3명이면?" 같은 후속 질문이 됩니다 |

### 평가

| 질문 | 결정 | 근거 |
|---|---|---|
| 정답은 어떻게 정하나? | 도메인 특화 질문 28개에 황금 답변을 직접 작성 | 미션 요구사항(황금 답변과 비교)입니다 |
| 채점은 믿을 수 있나? | 규칙 점수(핵심 수치·키워드)와 LLM 판정을 함께 사용 | 한쪽만 쓰면 놓치는 오답이 있어 둘을 맞춰 봤습니다 |
| 문서가 도움이 되는지는? | 문서 없이 답하는 기준선(E0)과 비교 | 검색이 없어도 맞히는 문제와, 검색이 꼭 필요한 문제를 구분하려는 목적입니다 |

### 서비스 · 안전

| 질문 | 결정 | 근거 |
|---|---|---|
| 무료 한도는? | 세션당 질문 수 제한과 선택형 접속 암호 | Groq 무료 한도(모델당 하루 20만 토큰)를 방문자가 함께 쓰기 때문입니다 |
| 키는 어디에? | Streamlit Secrets에만 저장, `secrets.toml`은 `.gitignore` | 저장소는 공개여도 키가 노출되지 않습니다 |
| 이상한 입력은? | 정규식 + LLM 가드레일이 프롬프트 인젝션·범위 밖 질문을 차단 | 시스템 지시 노출 요청 등에 정해진 안내문만 답합니다 |
| 메모리가 모자라면? | dense 모델이 못 올라가면 BM25만으로 계속 동작 | 무료 서버(CPU, 약 2.7GB)에서 앱이 멈추지 않게 하려는 장치입니다 |
| 답변 화면은? | 출처 쪽수·도구 호출 정보는 숨김 | 사용자에게 필요한 것은 답이고, 내부 정보는 확인용 스위치(`SHOW_DEBUG`)로만 봅니다 |

## 시스템 구조

```
질문 → 가드레일 → 에이전트(gpt-oss-120b)
                    ├─ search_tax_docs → BM25 + bge-m3 → RRF → 문서 조각
                    ├─ earned_income_deduction  (근로소득공제)
                    ├─ rent_tax_credit          (월세 세액공제)
                    ├─ pension_tax_credit       (연금계좌 세액공제)
                    └─ child_tax_credit         (자녀 세액공제)
                  → 답변 정리(출처 표기 제거) → 화면
```

배포용 앱은 노트북에서 미리 만든 검색 데이터(`chunks.jsonl`, `emb.npy`)를 읽습니다. 서버에서 PDF를 다시 처리하지 않고, 문서 벡터는 미리 계산해 둡니다.

## 직접 부딪힌 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 노트북 평가가 멈춘 것처럼 보임 | 느린 추론 모델이 출력 없이 오래 돎 | 진행 표시를 넣고, 느린 모델은 실행 여부를 스위치로 분리 |
| 판정 열이 NaN | 정의 시점에 판정 모델이 아직 `None` | 판정 모델을 필요할 때 만드는 방식으로 변경, 재판정 셀 추가 |
| Groq 429 오류 | 무료 하루 토큰 한도(TPD) 초과 | 한도가 풀릴 때까지 기다렸다 다시 시도하는 루프 (거절된 요청은 과금되지 않음) |
| 그래프의 한글이 깨짐 | Colab 기본 폰트에 한글 없음 | 한글 폰트를 등록하는 셀 추가 |
| Colab 사용량 제한 | 무료 사용량 소진 | 같은 코드를 VS Code(로컬)에서 실행해 검색 데이터를 만듦 |
| Streamlit "private app 1개만" | 무료 플랜 제한 | 저장소를 공개로 전환 (키는 저장소에 없음) |
| 남은 질문 수가 바로 안 줄어듦 | 사이드바를 답변 처리 전에 그림 | 자리를 비워 두었다가 답변 후에 갱신 |
| 월세 공제액이 틀리게 나옴 | 모델이 도구에 잘못된 숫자(이전 질문 값)를 넣음 | "지금 질문의 숫자만 쓴다"는 규칙을 프롬프트에 강화하고, 확인용 스위치로 입력값을 볼 수 있게 함 |
| 배포 후 `'NoneType' object has no attribute '__dict__'` | 코드 갱신 중 모듈이 다시 읽히며 `@dataclass`가 모듈 정보를 못 찾음 | `@dataclass`를 일반 클래스로 교체 |
| 답변 뒤 예시 질문을 누르면 사라지고 답이 없음 | 대화가 생기면 버튼을 그리지 않아 클릭이 무시됨 | 예시 질문을 접이식 상자로 항상 같은 자리에 둠 |

## 알려진 한계

- 무료 Groq 한도를 방문자가 함께 쓰므로, 한도가 차면 잠시 답하지 못합니다.
- 모델이 계산 도구에 숫자를 잘못 넣는 경우가 완전히 사라진 것은 아닙니다. 필요하면 월세 도구가 "월 월세 × 개월 수"를 직접 받게 바꿀 수 있습니다.
- 챗봇의 답은 참고용입니다. 실제 신고 전에는 국세청 안내를 확인하세요.
- 평가 세트가 28문항이라, 점수 차이를 일반적인 성능으로 해석하기에는 표본이 작습니다.

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 에이전트 | LangChain 1.x (`create_agent`, `@tool`), LangGraph |

## 실행 방법

```
pip install -r requirements-data.txt
python make_data.py "data\report.pdf"      # data/chunks.jsonl, data/emb.npy 생성
pip install -r requirements.txt
streamlit run app.py
```

Secrets(또는 `.streamlit/secrets.toml`)에 `GROQ_API_KEY`를 넣습니다. 선택으로 `APP_PASSWORD`, `MAX_QUESTIONS_PER_SESSION`을 둡니다.
